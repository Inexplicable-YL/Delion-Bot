# 0024. 非项目聊天的文件版本记录

- 状态：已接受
- 日期：2026-11-28

## 背景

非项目聊天的 privacy 与 share 目录没有版本管理。模型或用户改坏文件后无法复原，分支会话拿到的是空目录，重试和编辑重发也不会撤回上一轮写下的文件。

## 决定

- **版本库**：core 为每个非项目会话保存一份按内容寻址的版本库（`userData/chat-files/<会话>/`），覆盖 privacy 与 share 中 5 MiB 以下的普通文件。更大的文件只记录大小与修改时间，不保存内容，也不参与恢复。
- **来源**：版本库是一串改动事件，每个事件标明来源：模型的某一轮、用户、分支、重试前撤销。每轮开始前和结束后各扫描一次目录，轮次之外出现的差异记为用户改动，也包括系统文件管理器、终端和其他外部工具做的修改。
- **重试与编辑重发**：重新开始前，只撤销被替换的轮次里模型写下的改动。如果某个文件之后被用户改过，就保留用户的版本。
- **分支**：新会话拿到分支点下一轮开始前的文件状态，这个状态包含两轮之间用户做的修改；分支点之前的轮次记录一并复制，新会话也能撤销这些轮次。
- **展示**：轮次改动卡片只列出 share 中的改动。资料页提供只读的文件时间线，可以查看每个版本与上一版的差异。

## 后果

- 后台任务、子 Agent 和旁问在轮次结束后写下的文件会被记为用户改动；两轮之间的多次手动修改会合并成一个版本。
- 判断文件是否变化时，大小和修改时间都相同的文件会被视为未变化，在时间戳精度很粗的文件系统上，同一时刻内的改动可能漏记。
- 版本库随会话删除，不做其他回收。

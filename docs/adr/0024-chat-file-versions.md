# 0024. 非项目聊天的文件版本记录

- 状态：已接受
- 日期：2026-11-28

## 背景

非项目聊天的 privacy 与 share 目录没有版本管理。模型或用户改坏文件后无法复原，分支会话拿到的是空目录，重试和编辑重发也不会撤回上一轮写下的文件。用户还会在 Agent 运行期间自己改文件，两边的改动交错在一起，必须分清每一处改动是谁做的。

## 决定

- **版本库**：core 为每个非项目会话保存一份按内容寻址的版本库（`userData/chat-files/<会话>/`），覆盖 privacy 与 share 中 5 MiB 以下的普通文件。更大的文件只记录大小与修改时间，不保存内容，也不参与恢复。
- **逐次归属**：每次改动单独成为一个事件，事件标明来源：用户、某个会话（主会话或子 Agent）的某一轮、分支、重试前撤销。
  - Agent 的文件工具（write、edit、delete、mkdir、download_file）在执行期间锁住目标路径，结束后把这个路径的变化记给这次调用。
  - shell 命令和其他可能写文件的工具会打开一个归属窗口，窗口关闭时把期间的目录变化记给它。同一会话（含子 Agent）的前台命令串行执行，所以窗口之间不会重叠；后台命令不参与串行。
  - 应用内的保存、新建、导入、移动和删除会锁住对应路径，记为用户。
  - 目录监听器把其余变化在 100 ms 内记下：没有窗口打开时记为用户，有窗口打开时记给当前窗口。
  - 应用关闭期间的改动在下次加载时记为用户。
- **重试与编辑重发**：重新开始前，撤销被替换轮次及其子 Agent 的改动。如果某个文件之后被用户改过，就保留用户的版本。
- **分支**：新会话拿到分支点下一轮开始前的文件状态，并继承此前轮次的记录，所以新会话也能撤销这些轮次。
- **展示**：轮次改动卡片列出本轮（含子 Agent）在 share 中的净改动。资料页的时间线把同一来源的连续版本合并成一条显示。

## 后果

- 命令运行期间，用户在应用之外对同一目录做的改动会记给这条命令；后台命令与其他命令同时运行时，归属可能记错。
- 前台命令等待审批时会挡住同一会话其他命令的执行，未知工具（如 MCP）也按命令串行执行。
- 判断文件是否变化时，大小和修改时间都相同的文件会被视为未变化。
- 版本库随会话删除，不做其他回收。

# 0025. 非项目聊天的文件版本以 Git 存储

- 状态：已接受
- 日期：2026-11-28

## 背景

[0024](0024-chat-file-versions.md) 为非项目聊天的 privacy 与 share 目录建立了版本记录，存储是自建的按内容寻址文件和事件日志。Git 已经是应用的运行依赖，它的对象库、提交历史和差异输出可以直接承担同样的存储工作，自建格式没有必要。

## 决定

- **存储**：每个非项目会话在 `userData/chat-files/<会话>/` 保存一个裸 Git 仓库。树中的 `privacy/` 与 `share/` 对应两个目录；超过 5 MiB 的文件以 `.large/` 下的指针记录大小与修改时间，不保存内容。
- **归属仍由代码判断**：0024 中的路径锁、归属窗口、命令串行、目录监听和关闭期间记为用户的规则保持不变。Git 只负责存储，不参与判断改动属于谁，也不依赖模型的说明。
- **先记内存，后台落盘**：归属判断只扫描目录并在内存中记录改动，不启动 git 进程，所以不拖慢工具执行。路径工具只扫描自己的目标路径。命令窗口打开时，如果目录监听自上次全量扫描后没有收到变化，就跳过这次扫描。待写的改动由一个 `git fast-import` 进程在后台成批写成提交。还没写入的连续同来源改动合并为一次提交。读取历史、撤销、分支和冻结轮次改动前，先等待待写改动落盘。正常退出时最多等待 2 秒让待写改动落盘。一批写入失败时丢弃这批记录，内存回到已落盘的状态，之后的扫描把这些差异按当时的来源重新记录，所以一次失败不会挡住后续读写。
- **轮次边界**：轮次开始不单独提交，而是写进这一轮开始后的第一次提交的提交信息。分支取到下一轮之后第一次提交之前的状态。
- **分支**：新仓库取得源仓库到分支点为止的历史。分支前的轮次因此可以直接在新会话中撤销。
- 版本库只用底层命令读写，不检出工作区，也不读取用户的 Git 钩子与签名设置。仓库从不检出文件，所以关闭 NTFS 路径保护，Windows 保留名和反斜杠等文件名照常记录。git 命令不继承外部的 GIT_ 环境变量，超过 2 分钟视为失败。时间线读取已记录的历史，不重新扫描目录，靠目录监听保持最新。

## 后果

- 应用异常退出、正常退出超过等待时间，或一批写入失败时，还没落盘的改动会丢失归属，记为用户或当时打开的命令。
- 同一轮次内连续的工具改动在历史中合并，单次工具调用的中间版本不一定保留。
- 文件模式只区分普通与可执行，恢复时按 644 或 755 设置权限。
- 文件名含控制字符的文件不记录版本。
- 命令开始前片刻的用户改动，如果目录监听还没送达事件，会记给这条命令。
- 未找到 git 时无法记录版本，轮次改动卡片显示为不可用。
